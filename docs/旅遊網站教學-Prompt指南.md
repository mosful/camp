## 給教學者（你）的說明

### 這份指南的設計原則

1. **每個 Phase 的 prompt 都是自給自足的。** 可以一段一段貼（建議第一次這樣做，比較好掌握進度），也可以照[附錄 A](#附錄-a一次全部貼上版)一次全部貼上。
2. **每段 prompt 都明確告訴 AI「對方是新手」**，要求它用白話解釋、每一步都說明在做什麼，並在需要朋友親手操作的地方停下來（標示 🛑）。
3. **範本只拿來「學結構」，不拿來「抄內容」。** `camp` 裡有約 20 位真實成員的全名、分房與訂餐明細。prompt 裡已經寫死「範本中的人名、電話、金額一律不得出現在新網站」，請不要刪掉這段。
4. **AI 會自己安裝工具。** 朋友只需要手動裝一個 Claude App（Phase 0），其餘的 Git、GitHub CLI、Node.js 都由 AI 透過 Windows 內建的 `winget` 安裝。

### 朋友實際需要親手做的事（只有這些）

| 時機 | 要做的事 | 為什麼 AI 不能代勞 |
|---|---|---|
| Phase 0 | 註冊 Claude、註冊 GitHub、安裝 Claude App | 帳號與付款必須本人操作 |
| Phase 1 | 在跳出的「是否允許此 App 變更裝置」視窗按「是」 | Windows 安全機制 |
| Phase 1–8 | AI 要執行指令前會問「允許嗎？」，按允許 | Claude Code 的安全機制 |
| Phase 2 | 在瀏覽器裡登入 GitHub、貼上一次性代碼 | 帳號登入必須本人操作 |
| Phase 3 | 把行程表、訂房截圖等素材丟進指定資料夾、回答 AI 的問題 | 只有朋友知道旅遊內容 |
| Phase 8 | 確認「哪些個資可以公開」 | 隱私決定權在本人 |

### 費用

- **Claude**：要能讓 AI 在電腦上操作檔案（Claude Code），需要**付費方案（Pro 以上）**。免費方案只能聊天，無法照這份指南走。
- **GitHub**：免費。免費帳號的 GitHub Pages **只能用公開（public）repo**，也就是說程式碼和網頁內容任何人都看得到——這點在 Phase 8 會再提醒。

### 建議的教學方式

第一次請你陪朋友（或遠端分享畫面）走完 Phase 0–2，因為安裝、登入這段最容易卡住。
Phase 3 之後就是「丟素材 → 看 AI 做 → 用手機檢查」的循環，朋友通常可以自己來。

## Phase 0｜手動前置作業（唯一不能靠 prompt 的部分）

> 這一段沒有 prompt，因為 AI 還沒裝好，只能手動。照順序做即可。
> 以下以 **Windows 10 / 11** 為主；Mac 的差異寫在最後。

### 0-1 註冊 Claude 並升級方案

1. 用瀏覽器開 <https://claude.ai>，用 Email 或 Google 帳號註冊。
2. 左下角頭像 → 設定／方案，升級為 **Pro**（或更高）。

### 0-2 註冊 GitHub

1. 開 <https://github.com/signup> 註冊。
2. **使用者名稱（username）會出現在網址裡**，例如帳號叫 `amy-travel`，網站網址就會是 `https://amy-travel.github.io/…`。建議取簡短、全小寫英文、好唸的名字。
3. 記得到信箱收驗證信。

### 0-3 安裝 Claude App

1. 開 <https://claude.ai/download>，下載 Windows 版並安裝。
2. 開啟後登入剛剛的 Claude 帳號。
3. 在 App 裡切換到 **Code**（Claude Code）分頁。
   - 第一次使用會要你**選一個資料夾**當工作目錄：先建立並選擇 `文件\旅遊網站`（`C:\Users\你的名字\Documents\旅遊網站`）。之後所有東西都會放在這裡。
   - **若 App 提示需要先安裝 Git**：照提示點連結安裝即可（一路按「下一步」用預設值）。或者開「開始選單 → 輸入 PowerShell → 開啟」，貼上下面這一行後按 Enter：

     ```powershell
     winget install --id Git.Git -e --accept-source-agreements --accept-package-agreements
     ```

     裝完把 Claude App 完全關掉再打開。

> **為什麼一定要用 Code 分頁？** 一般的聊天模式只能「回答」，不能在你的電腦上建立檔案、執行安裝指令。Code 分頁才是能真正動手做事的 AI 助手。

### 0-4 準備旅遊素材

先把手邊有的資料蒐集起來，不用整理，**截圖、PDF、LINE 對話複製貼上的文字都可以**：

- 行程表（每天幾點去哪裡）
- 住宿訂房確認（名稱、地址、電話、入住退房時間、房間分配）
- 餐廳訂位或點餐資訊
- 門票、預約單、交通（租車、高鐵、接駁）
- 分工名單（誰開車、誰負責什麼）
- 想放的封面照片（可有可無）

Phase 3 會告訴朋友要把這些放在哪裡。

### 0-x Mac 使用者的差異

- Claude App 一樣到 <https://claude.ai/download> 下載 Mac 版。
- Mac 沒有 `winget`，Phase 1 的 prompt 已經寫好「如果是 Mac 就改用 Homebrew」，AI 會自己判斷。安裝 Homebrew 時會要求輸入**電腦開機密碼**（輸入時畫面不會顯示字，是正常的）。

## Phase 1｜安裝與檢查開發工具

**目的**：讓 AI 自己把後面會用到的工具裝好，並確認每一樣都能用。

**會裝的東西**

| 工具 | 用途 | 白話解釋 |
|---|---|---|
| Git | 版本紀錄 | 像是遊戲存檔，每次改完都存一格，改壞了可以讀檔回去 |
| GitHub CLI（`gh`） | 跟 GitHub 溝通 | 讓 AI 能幫你在 GitHub 上建立網站、上傳檔案 |
| Node.js | 手機版截圖檢查 | 讓 AI 能模擬手機開網頁、截圖給你看（Phase 7 用） |

**朋友要做的事**：AI 要執行指令時會問「允許嗎？」→ 按允許；Windows 跳出「是否允許此 App 變更裝置」→ 按「是」。

### Prompt 1

```text
【Phase 1：安裝與檢查開發工具】

背景說明（請先讀完再動作）：
- 我是完全沒有寫過程式、也第一次用 AI 助手的新手。
- 我想做一個「一頁式旅遊手冊網站」，給同行的朋友用手機查看行程、導航、住宿資訊。
- 之後會拿一個現成的範本（GitHub 上的 mosful/camp）當參考。
- 這一步只要把工具裝好，先不要做網站。

請你這樣跟我互動：
1. 全程使用繁體中文（台灣用語），避免專有名詞；一定要用到時，用一句白話解釋。
2. 每執行一個指令前，先用一句話告訴我「這一步在做什麼、為什麼要做」。
3. 遇到需要我親手操作的地方（例如跳出視窗要按「是」），用「🛑 請你做：」開頭清楚告訴我要按哪裡，然後停下來等我回覆「好了」。
4. 出錯時不要丟一大串英文錯誤訊息給我，先自己嘗試修正；真的需要我幫忙時，用白話說明發生什麼事。

請依序完成：
A. 判斷我的作業系統（Windows 或 Mac）和版本，告訴我結果。
B. 檢查以下工具是否已安裝，並列成表格（工具名稱／是否已安裝／版本）：
   - Git
   - GitHub CLI（gh）
   - Node.js（LTS 版即可）
C. 把缺少的工具裝起來：
   - Windows：使用 winget，指令要加上 --accept-source-agreements --accept-package-agreements 以免卡在同意條款。
     套件 ID 參考：Git.Git、GitHub.cli、OpenJS.NodeJS.LTS
   - Mac：先檢查有沒有 Homebrew，沒有的話先告訴我要裝 Homebrew 而且會需要輸入電腦密碼，等我同意後再裝；接著用 brew 安裝 git、gh、node。
D. 安裝後，新裝的工具可能要重開終端機才找得到。如果遇到「找不到指令」，請改用完整路徑執行，或重新整理環境變數（PATH），不要叫我重開機，除非真的沒有其他辦法。
E. 設定 Git 的基本資料：
   - 先問我要用什麼名字和 Email（告訴我：這會出現在網站的修改紀錄裡，是公開的，可以用暱稱；Email 可以等 Phase 2 登入 GitHub 後改用 GitHub 提供的隱私信箱）。
   - 拿到後執行 git config --global user.name 和 user.email。
   - 另外設定 git config --global init.defaultBranch main
   - Windows 另外設定 git config --global core.autocrlf true 和 git config --global core.quotepath false（讓中文檔名正常顯示）。
F. 最後再檢查一次所有工具，用表格回報結果，並用一句話告訴我「Phase 1 完成，可以進行 Phase 2」。

注意：
- 不要安裝我沒提到的其他軟體。
- 不要修改任何系統設定（除了上面列出的 git config）。
```

**預期結果**：AI 回報一張表，Git、gh、Node.js 都顯示已安裝和版本號。

## Phase 2｜登入 GitHub、下載範本、建立專案資料夾

**目的**：
1. 讓 AI 能用朋友的 GitHub 帳號做事（登入一次就好）。
2. 把 `camp` 範本下載下來「參考用」。
3. 另外建立一個全新的、乾淨的專案資料夾（**不是**直接複製 camp，避免把別人的個資帶過去）。

**朋友要做的事**：AI 會打開一個新視窗和瀏覽器，畫面上會出現一組像 `ABCD-1234` 的代碼 → 在瀏覽器登入 GitHub、貼上代碼、按 Authorize。

### Prompt 2

```text
【Phase 2：登入 GitHub、下載範本、建立專案資料夾】

背景：我是新手（請沿用 Phase 1 的互動方式：繁體中文、白話、每步說明、需要我動手時用「🛑 請你做：」並停下等我）。
Phase 1 已經安裝好 Git、GitHub CLI、Node.js。

請依序完成：

A. 登入 GitHub
   1. 先執行 gh auth status 檢查是否已登入。已登入就跳到 A-4。
   2. 未登入的話：因為登入流程需要我在畫面上互動，請「另開一個新的終端機視窗」執行登入指令，不要在你自己的環境裡執行（你那邊無法互動，會卡住）。
      - Windows 可用：Start-Process powershell -ArgumentList '-NoExit','-Command','gh auth login --hostname github.com --git-protocol https --web'
      - Mac 可用：osascript 開一個 Terminal 視窗執行 gh auth login --hostname github.com --git-protocol https --web
   3. 🛑 用白話告訴我接下來會發生什麼：新視窗會顯示一組 8 碼代碼 → 按 Enter 會開瀏覽器 → 登入 GitHub → 貼上代碼 → 按綠色的 Authorize 按鈕 → 看到成功畫面後回來告訴你「好了」。然後停下來等我。
   4. 我回覆後，執行 gh auth status 確認登入成功，並告訴我登入的 GitHub 帳號名稱。
   5. 執行 gh auth setup-git，讓之後上傳檔案不用再輸入密碼。
   6. 用 gh api user 查出我的 GitHub 帳號 ID，告訴我可以改用「ID+帳號@users.noreply.github.com」當 Git 的 Email 來保護隱私，問我要不要換。我同意就幫我改 git config --global user.email。

B. 下載範本（只當參考，不在裡面修改）
   1. 在我的「文件」資料夾底下建立「旅遊網站」資料夾（已存在就沿用）。
      Windows：%USERPROFILE%\Documents\旅遊網站；Mac：~/Documents/旅遊網站
   2. 在「旅遊網站」裡執行：git clone https://github.com/mosful/camp.git _範本-camp
   3. 讀一下 _範本-camp 裡的 README.md、CLAUDE.md、index.html，用 5～8 行白話向我介紹這個範本網站有哪些區塊、有什麼好用的功能（例如一鍵導航、倒數計時、手機版表格變卡片）。
   4. 提醒我：範本裡有別人的真實姓名和個資，我們只學它的「版型和做法」，內容一律不會照抄。

C. 建立我自己的專案資料夾
   1. 🛑 問我兩件事，然後停下來等我回覆：
      (1) 這趟旅行的名稱（例如「2026 花蓮三天兩夜」）
      (2) 網址要用的英文代號：只能用小寫英文、數字、減號，例如 hualien-2026。
          請先根據旅行名稱幫我建議 2～3 個，並說明最後網址會長成 https://<我的GitHub帳號>.github.io/<英文代號>/
   2. 拿到回覆後，在「旅遊網站」資料夾裡建立以英文代號命名的資料夾，例如 旅遊網站\hualien-2026。
   3. 在裡面建立以下結構：
      <英文代號>/
        素材/        ← 我之後把截圖、PDF、文字丟這裡
        sources/     ← 你整理後的文字資料
        .gitignore   ← 先放一個空的就好，Phase 8 前會補內容
   4. 在這個資料夾執行 git init。
   5. 用白話告訴我：
      - 我的專案資料夾完整路徑是什麼
      - 「素材」資料夾要放什麼（行程表、訂房確認、餐廳、門票、交通、分工名單、想用的封面照片；截圖、PDF、文字檔都可以，檔名隨意）
   6. 🛑 告訴我：請在 Claude App 把工作資料夾切換到這個新的專案資料夾（說明在哪裡切換），切換後再進行 Phase 3。

完成後回報：「Phase 2 完成」，並列出：GitHub 帳號、旅行名稱、英文代號、專案資料夾路徑、預計網址。
```

**預期結果**：朋友有一個 `文件\旅遊網站\<英文代號>` 資料夾，裡面有空的 `素材`、`sources`，並知道最後網址長怎樣。

> **教學者小提醒**：切換工作資料夾很重要。之後 AI 會在「目前的資料夾」裡找 `CLAUDE.md`，資料夾選錯，AI 就讀不到專案規則。

## Phase 3｜整理旅遊素材

**目的**：AI 讀完朋友丟進來的截圖、PDF、文字，整理成乾淨的文字檔（`sources/*.md`），並主動列出「還缺什麼資訊」。這一步做好，後面網站內容才不會亂編。

**朋友要做的事**：把 Phase 0-4 準備的素材全部丟進 `素材` 資料夾 → 貼 prompt → 回答 AI 提的問題。

> 💡 也可以把截圖直接拖曳進 Claude App 的對話框，效果一樣。

### Prompt 3

```text
【Phase 3：整理旅遊素材】

背景：我是新手（沿用之前的互動方式：繁體中文、白話、需要我動手時用「🛑 請你做：」並停下）。
我已經把旅遊資料放進目前專案的「素材」資料夾（也可能有些直接貼在這則訊息下面或附在對話中）。

請依序完成：

A. 盤點素材
   列出「素材」資料夾裡每個檔案，用表格說明：檔名／檔案類型／你看出來的內容摘要（一行）。
   圖片和 PDF 請實際打開閱讀，不要只看檔名猜。看不清楚的地方請標記「⚠️ 看不清楚」。

B. 整理成 sources/ 底下的 Markdown 檔，依照以下分類（沒有該類資料就不要建立該檔）：
   - sources/01-行程總表.md        每天：日期、時間、活動、地點名稱
   - sources/02-住宿.md            住宿名稱、地址、電話、入住/退房時間、房型、分房、費用
   - sources/03-餐食.md            每一餐：時間、餐廳、地址、電話、是否訂位、點餐明細、金額
   - sources/04-地點與導航.md      所有會去的地點：名稱、地址、電話、營業時間（一地點一列）

   - 決定不上傳的檔案或資料夾寫進 .gitignore（預設寫入：素材/），每一行上面用繁體中文註解原因
   - 同步更新 CLAUDE.md 的「隱私注意事項」，記錄我的決定
   - git commit

C. 建立 GitHub repo 並上傳
   1. 先執行 git status，確認沒有不該上傳的檔案被追蹤（例如素材、node_modules、截圖）
   2. 確認目前分支名稱是 main
   3. gh repo create <英文代號> --public --source=. --remote=origin --push
      （如果名稱已被使用，告訴我並建議其他名稱）

D. 開啟 GitHub Pages
   1. gh api -X POST repos/<帳號>/<英文代號>/pages -f "source[branch]=main" -f "source[path]=/"
   2. 每 20 秒用 gh api repos/<帳號>/<英文代號>/pages/builds/latest 查一次部署狀態，最多查 5 分鐘，直到 status 為 built
   3. 用 curl 或其他方式確認 https://<帳號>.github.io/<英文代號>/ 回應正常（HTTP 200）

E. 建立 README.md
   參考 ../_範本-camp/README.md 的寫法，寫上：網站名稱、線上網址、之後要怎麼改內容（用 Claude 講需求 → commit → push）、本機預覽方式。
   commit 並 push。

F. 最後告訴我：
   - 🎉 公開網址（用手機可以直接點的完整網址）
   - 🛑 請我用「自己的手機」打開網址，測試：導覽列滑動、一個導航按鈕、一個撥號按鈕
   - 教我如何把網址「加入主畫面」（iPhone：Safari 分享 → 加入主畫面；Android：Chrome 選單 → 加到主畫面），方便旅途中快速打開
   - 回報「Phase 8 完成」
```

**預期結果**：拿到 `https://<帳號>.github.io/<英文代號>/`，手機打得開。

```text

```

## 附錄 A｜一次全部貼上版

如果朋友想一次貼完就讓 AI 一路做下去，請照這個順序組合成**一則訊息**：

1. 先貼下面的「總控 prompt」
2. 接著把 **Prompt 1 到 Prompt 8** 的內容依序貼在後面（每段保留原本的【Phase N】標題）
3. 如果有素材文字，貼在最後

> **注意**：即使一次貼上，AI 還是會在所有 🛑 的地方停下來等朋友回覆（登入 GitHub、確認區塊、確認個資等），這是刻意的，不是當機。朋友回覆後打一句「繼續」，AI 就會接著做。

### 總控 prompt

```text
【總控說明：請先讀完這一段】

我是完全不會寫程式的新手。接下來這則訊息裡有 Phase 1 到 Phase 8 的工作說明，目標是從零做出一個「一頁式旅遊手冊網站」並放上 GitHub Pages。

執行規則：
1. 依照 Phase 1 → Phase 8 的順序執行，前一個 Phase 沒有完成（或我還沒回覆 🛑 的問題）之前，不可以開始下一個。
2. 所有標示「🛑」的地方都必須停下來等我回覆，即使你覺得可以自己決定也一樣。特別是：GitHub 登入、區塊確認、個資是否公開、素材是否上傳。
3. 每完成一個 Phase，先用 3 行以內的白話告訴我「剛剛完成了什麼、下一步要做什麼」，再繼續。
4. 一開始先用一個清單列出 Phase 1～8 的標題，之後每完成一個就打勾，讓我知道進度。
5. 如果中途對話被中斷，我會跟你說「繼續」，請先檢查目前進度（看資料夾裡有哪些檔案、git log 紀錄、gh auth status），從還沒完成的 Phase 接著做。
6. 全程使用繁體中文（台灣用語），白話說明，避免專有名詞。
7. Phase 2 之後，請在專案資料夾內作業；如果 App 的工作資料夾還不是專案資料夾，請提醒我切換。切換後我會說「繼續」，請先讀專案的 CLAUDE.md（若已存在）。

以下是各 Phase 的內容：
```

> **教學者小提醒**：一次全貼很方便，但對話會變得很長。若中途 AI 回應變慢或開始忘記前面的規則，請朋友開一個**新對話**，貼上「總控 prompt」＋**還沒做的 Phase**，再加一句「Phase 1～N 已完成」即可接續。到了 Phase 4 之後有 `CLAUDE.md`，新對話的 AI 會自動讀到專案規則，接續起來會很順。

## 附錄 B｜疑難排解

| 狀況 | 原因 | 解法（直接貼給 AI） |
|---|---|---|
| AI 說「找不到 git／gh／node」 | 剛裝好，環境變數還沒更新 | 「請重新整理 PATH 或用完整路徑執行；真的不行再告訴我要重開哪個程式」 |
| `winget` 找不到 | Windows 太舊或缺「應用程式安裝程式」 | 到 Microsoft Store 搜尋「應用程式安裝程式（App Installer）」更新後再試 |
| GitHub 登入一直卡住 | 登入指令在 AI 自己的環境跑，沒辦法互動 | 「請另開一個新的終端機視窗執行 gh auth login --web」 |
| 中文檔名顯示成 `\346\227\205…` | Git 預設會跳脫中文 | 「請執行 git config --global core.quotepath false」 |
| 網址打開是 404 | Pages 剛開啟還在部署，或 repo 名稱打錯 | 等 2 分鐘；或貼「請檢查 GitHub Pages 部署狀態和網址」 |
| 手機看到的還是舊內容 | 手機瀏覽器快取 | 網址後面加 `?v=2` 重新開，或關掉分頁重開 |
| 手機版可以左右滑 | 某個元素太寬 | 貼 Prompt 7 重新檢查 |
| 導航按鈕開到錯的地方 | 地址或地點名稱不精確 | 「請重新查證 XX 的地址，並更新導航連結」 |
| AI 自己編了一個地址 | 素材沒寫、AI 補了 | 「請只用 sources/ 和查證過的資料，查不到就標記問我」 |
| 不小心把素材上傳了 | `.gitignore` 沒設好 | 「我不小心上傳了素材資料夾，請幫我從 repo 移除並加入 .gitignore，並說明 git 歷史裡是否還看得到」 |

## 附錄 D｜Plan B：完全不安裝的雲端做法

如果朋友的電腦是公司電腦、不能裝軟體，或是只有平板，可以改用**網頁版 Claude Code**（<https://claude.ai/code>），AI 在雲端的電腦上作業，自己的電腦什麼都不用裝：

1. 照 Phase 0 註冊 Claude（Pro）和 GitHub。
2. 在 GitHub 網頁右上角「＋」→ New repository，建立一個 **public** 的空 repo（名稱用英文代號，勾選 Add a README）。
3. 開 <https://claude.ai/code>，依畫面指示連結 GitHub 帳號，並選擇剛剛建立的 repo。
4. 接著從 **Prompt 3** 開始用，但要調整：
   - 素材改成**直接把截圖拖進對話框**（不要放進 repo，避免公開）
   - 每段 prompt 開頭加一句：「範本請從 https://github.com/mosful/camp 讀取（git clone 到暫存資料夾，不要放進我的 repo）。」
   - 跳過 Prompt 1、2（雲端環境已經有工具）；Prompt 8 的 C 段改成「push 到 main」即可，D 段開 Pages 若沒有權限，就到 GitHub 網頁 repo 的 Settings → Pages，Source 選 `main` / `/ (root)` 手動開啟。
5. 雲端做法的限制：AI 改完通常會開一個 PR（合併請求），需要在 GitHub 網頁上按「Merge」才會上線；想省略這步可以在 prompt 裡寫「直接推到 main，不要開 PR」。

本機版（Phase 0–8）和雲端版做出來的網站完全一樣，差別只在 AI 在哪台電腦上工作。
